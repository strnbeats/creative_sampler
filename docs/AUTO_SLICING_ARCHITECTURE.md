## 1. Аудит текущей реализации

| Компонент | Что есть в коде | Следствие для Auto Slicing |
| --- | --- | --- |
| Импорт и источник | [AudioImportService](../src/import/AudioImportService.cpp) декодирует файл и строит waveform асинхронно. Импорт ограничен числом кадров, представимым в `int`, и бюджетом декодированных данных 2 GiB. [SampleStorage](../src/sample/SampleStorage.h) хранит неизменяемые PCM и метаданные (source rate, число кадров, каналов, bit depth). [PluginProcessor::handleImportResult](../src/plugin/PluginProcessor.cpp) после успешного импорта создаёт новый sample ID даже для того же файла, устанавливает один слайс на весь файл при достаточной длине и запускает анализ. Неудачный импорт сохраняет прежний источник. | План привязан к конкретной загрузке, а не пути файла. Worker удерживает `SampleHandle`; копировать PCM не нужно. |
| Waveform | [WaveformData::generate / chooseLevel](../src/waveform/WaveformData.h) строят уровни min/max по каналам с `framesPerPeak`. | Пики подходят для отображения и грубой оценки энергии. Уточнение атаки или тихого участка требует PCM либо специально рассчитанных признаков. |
| Жизненный цикл анализа | [AnalysisCoordinator::requestAnalysis / workerLoop / run](../src/analysis/AnalysisCoordinator.cpp) используют worker, токен отмены и пару `AnalysisIdentity{sampleId, generation}`. Анализаторы выполняются последовательно (Processor заказывает BPM, key, transients). Публикуется итог, проверенный на актуальность; ошибка одного анализатора завершает текущий запрос ошибкой без частичных результатов. `latestResult()` отдаёт копию под mutex. | Переиспользовать готовый итог один раз на поколение. Не копировать массив признаков на каждом тике UI и не читать coordinator из callback. Для V1 ждать терминального результата. Частичные результаты и разделение критического пути с Key стоит рассматривать после замеров. |
| Транзиенты | [TransientAnalyzer::analyze](../src/analysis/TransientAnalyzer.cpp) использует спектральную новизну, энергию и HFC, уточняет позицию атаки, объединяет близкие события. [Transient / TransientAnalysis](../src/analysis/AnalysisTypes.h) дают `samplePosition`, секунды, нормализованную координату, strength, optional confidence и spectral flux. По умолчанию окно 12 мс, шаг 1 мс, минимальная дистанция событий 12 мс и максимум 65 536 хранимых событий. Есть totalEventCount и статус truncation. Strength нормализована внутри файла, confidence эвристическая. Для stereo используются поканальные признаки с объединением энергии. | Использовать native позиции и оценки. Дистанция детектора задаёт разрешение обнаружения, а музыкальная минимальная длительность задаётся выше. Truncated не гарантирует репрезентативность по всей длине. |
| Темп и тональность | [BPMAnalyzer::analyze](../src/analysis/BPMAnalyzer.cpp) оценивает период по автокорреляции novelty, отдаёт темп, score, эвристическую confidence, альтернативы и octaveAmbiguous. По умолчанию диапазон 50–220 BPM, минимальная длина 1,5 с, минимум четыре onset и три цикла. Внутренний порог lowConfidence составляет 0,38. `BpmAnalysis::effectiveValue()` учитывает optional manual override. [KeyAnalyzer](../src/analysis/KeyAnalyzer.cpp) оценивает тонику/лад и уверенность по всему материалу. | Beat phase, downbeat, метр, локальные аккорды и фразовые границы отсутствуют. Коррекция BPM задаёт период, но не фазу. Key можно показать в UI, границы из него не выводятся. |
| Slice model | [SliceEngine / Slice](../src/slice/SliceEngine.h) и [makeSlice / allocateId / isValid](../src/slice/SliceEngine.cpp) хранят сортированные непересекающиеся полуоткрытые диапазоны с возможными пропусками, ID, MIDI note и параметрами. Единица — исходный PCM кадр на общей оси каналов. Минимум по умолчанию 64 кадра. ID монотонный в экземпляре движка, переживает импорт; revision также меняется при правках параметров. Есть create/split/delete/move/reset/setMidiNote, batch replace и provenance отсутствуют. | Полная замена потребует отдельной транзакции. Состояние «валидный файл короче 64 кадров» сейчас даёт пустой список; транспорт целого семпла остаётся отдельным путём. |
| MIDI и snapshot | [SlicePlaybackSnapshot::create](../src/playback/SlicePlaybackSnapshot.cpp) пинит источник и копирует диапазоны, параметры и таблицу списков regions по нотам 0–127. [SlicePlaybackEngine::startNote / releaseNote](../src/playback/SlicePlaybackEngine.cpp) запускает regions одной ноты и отпускает голоса по ноте. Пул на 16 voices с вытеснением; это предел полифонии, а не числа слайсов. `makeSlice` назначает `60 + (id − 1) mod 68`, то есть численно 60–127. В SliceEngine нет отдельного лимита числа слайсов. | Первый слайс новой загрузки может получить ноту, отличную от 60. После wrap общая нота может запускать несколько regions. Автоматическому kit нужны явные слоты и ноты. |
| Публикация и WebView | [PluginProcessor::timerCallback / publishSliceSnapshotIfNeeded](../src/plugin/PluginProcessor.cpp) создают и публикуют snapshot по изменению revision и освобождают старые. [PluginEditor](../src/plugin/PluginEditor.cpp) и [protocol.ts](../web-ui/src-v2/bridge/protocol.ts) передают sample ID, sliceRevision, slices с MIDI, analysis generation и waveform. Ревизия ресурса sample сейчас сериализуется как строка «1». Native snapshot UI ограничивает transient markers 2048. Production UI-v2 имеет навигацию и параметры слайса, Play/Stop относится к целому семплу. Ручные split/delete/move доступны через [нативный редактор](../src/ui/WaveformEditorComponent.cpp); React потребуются отдельные действия для полного редактирования. | Planner должен брать native результат. Для auto status, замены плана и software pads понадобятся новые контракты. `getStateInformation/setStateInformation` сейчас сохраняют APVTS, а не kit и аудио. Сохранение редактирования между перезапусками требует отдельного решения. |

В расчётах время кадра равно `frame / sourceRate`, границы лежат в `[0, N]`, диапазоны слайсов полуоткрытые, последняя граница равна `N`. TransientAnalyzer нормализует позицию события через `max(1, N−1)`; UI и planner должны строить координаты границ от целых кадров, выделяя `N` как конец файла. Host sample rate нужен воспроизведению, а не геометрии плана.

## 2. Pipeline и потоки

```mermaid
flowchart LR
    I["Импорт · PCM и метаданные"] --> A["AnalysisCoordinator · worker"]
    A --> C["Кандидаты и признаки · worker"]
    C --> M["Выбор стратегии и границ · worker"]
    M --> P["AutoSlicePlan · валидация"]
    P --> G["Проверка ключа и ревизии · message thread"]
    G --> S["SliceEngine · одна транзакция"]
    S --> U["UI · общий kit для Basic и Advanced"]
    S --> H["Immutable playback snapshot"]
    H --> D["Audio callback · готовая карта нот"]
```

| Этап | Вход и выход | Отказы и отмена |
| --- | --- | --- |
| Регистрация источника | Processor фиксирует handle, метаданные, новый ID. Для импорта в Basic ставит задачу подготовки. Импорт в Advanced сохраняет текущий whole-file workflow; при первом переходе после такого импорта доступна явная генерация. | При неудачном импорте прежний kit остаётся доступным. На успешной замене отменяются задачи старого источника и сбрасывается его runtime selection. |
| Сбор анализа | Planner получает один валидированный native AnalysisResult нужного поколения. Кандидаты получают силу атаки, локальный фон и свидетельства сетки/паузы. Достаточны immutable PCM, transient и BPM; тональность вне выбора стратегии. | Отсутствие ритма и пустые transients являются нормальными входами. При ошибке анализа V1 использует целый источник и сообщает о fallback. Невалидный источник отклоняется. |
| Интерпретация и оптимизация | Чистый planner на worker выбирает стратегию и упорядоченные границы. Число кандидатов ограничено по временным окнам после ранжирования с сохранением наиболее сильного события в каждом окне. | Проверять отмену при обходе PCM, кандидатов, поиске phase и решении задачи выбора. При превышении бюджета использовать допустимый более простой результат; cancelled не публикуется. |
| Валидация | Planner выдаёт готовый immutable план или reason. Валидатор проверяет метаданные, порядок, покрытие, диапазоны, число и минимальные длины. Message thread повторяет дешёвые инварианты перед применением. | Отбракованный план не меняет рабочую коллекцию. На первом импорте остаётся provisional whole-file slice, если он доступен. |
| Commit и публикация | Message thread проверяет request ID, sample ID/revision, analysis generation и исходную sliceRevision; подготавливает полную модель и snapshot, затем публикует новую revision одним действием модели. | Устаревший результат отбрасывается. Allocation failure и отказ публикации сохраняют прежний kit. UI получает отдельные состояния preparing, ready, fallback и error, не смешанные со статусом импорта. |

На worker передаётся ключ `{sampleId, sourceRevision, analysisGeneration, baseSliceRevision, requestId}` и копия политики. Для immutable источников V1 идентичность PCM обеспечивает новый sample ID, sourceRevision может оставаться 1. Независимый requestId отменяет повторную нарезку даже при переиспользовании анализа. В одном экземпляре плагина держать одну активную и одну последнюю ожидающую задачу. Worker выдаёт результат в очередь владельцу модели и не трогает SliceEngine/React. На завершении плагина отменить задачи и дождаться их вне audio callback, исключив поздние вызовы к уничтоженному Processor.

Проверка полного `baseSliceRevision` консервативна и предотвращает потерю даже правок громкости, включая сделанные во время подготовки. При конфликте показать доступный текущий kit и предложить заново запустить операцию. Отдельный structural revision имеет смысл лишь при доказанной необходимости и с повторным объединением параметров при commit.

## 3. Стратегии и правила выбора

| Стратегия | Правило | Применение в первой версии |
| --- | --- | --- |
| Transient | Оценить onset по strength, confidence, росту энергии относительно локального фона и спектральной новизне. Отсутствующую confidence считать отсутствующей информацией. В кластере конкурирующих атак выбрать наиболее ясную; сохранять сильные разнесённые атаки и не расходовать весь бюджет на один плотный участок. | Основной путь для перкуссии и уже нарезанного вокала с отчётливыми разделителями. При слабом контрасте оставить меньше границ. |
| Beat | Предложить период `sourceRate × 60 / BPM`. Оценить phase по взвешенному совпадению onset с сеткой, проверить поддержку по разным участкам, альтернативы ×½/×2 и стабильность остаточной ошибки. При равенстве кандидатов или при плавающем темпе отказаться от сетки. Для шага меньше доли нужны подтверждённые subdivisions. | Внутренний источник кандидатов для Hybrid. Чистый Beat после проверки пользовательского сценария. Четверти, восьмые и шестнадцатые здесь означают интервалы 1, ½ и ¼ beat при предположении четвертного пульса. Полтакта, такт, триоли и фразы требуют дополнительного свидетельства размера, downbeat или subdivision. |
| Hybrid | Сетка повышает оценку близких кандидатов и может предложить разрез в длинном спокойном интервале. Сильную атаку сохранить на её кадре. Слабое событие можно заменить близким тихим краем сетки, если это не режет атаку или устойчивый тон. Стартовый радиус сопоставления `min(25 мс, 0,08 beat)`, уточняется на корпусе. | Основной путь для устойчиво ритмичных melodic/drum loops. Слабая phase или BPM confidence возвращает Transient либо fallback. |
| Equal / Creative | Для явного количества делить `N` на целые интервалы, проверять минимальную длину. Творческий вариант выбирает тихие точки вокруг опор равного деления либо сохраняет подтверждённые атаки; любое будущее случайное решение требует seed. | Отложить как явные режимы для текстур и экспериментов. Автоматический fallback V1 сохраняет целый файл при отсутствии достоверных границ. |

Оценки анализа являются эвристиками. Порог BPM детектора служит исходным фильтром, а гипотеза phase должна иметь независимую проверку. Сильный onset вне сетки может быть синкопой. Не считать края файла первой долей; ведущая тишина и pickup входят в исходную шкалу.

Предлагаемая политика V1, числа служат стартовыми параметрами калибровки:

- Целевой kit обычно 4–16 частей, допустимы 1–32, для короткого файла — один целый слайс. При `N < minimumSliceLength` остаётся транспорт и явный статус отсутствия playable kit. Hard cap 32 относится к auto plan; он не изменяет лимиты ручного редактора. Число также ограничено `floor(N / minFrames)` с отдельным whole-file fallback.
- `minFrames = max(engineMinimum, ceil(sourceRate × musicalMinSeconds))`. Начать калибровку с 60 мс для плотных атак и 120 мс для связных/тональных фрагментов. Стратегия штрафует слишком длинные сегменты при наличии надёжного места разреза, например после 4 устойчивых beat или 2 с без сетки. Универсальный жёсткий максимум конфликтует с длинными текстурами, целыми фразами и лимитом 32. Допускать длинные сегменты, когда безопасного разреза нет.
- Выбрать границы по суммарной полезности, штрафу за число и слишком близкие/длинные интервалы. Использовать ограниченный поиск или DP по прореженному списку с детерминированным tie-break по качеству и исходному кадру. Уменьшать число частей по мере падения полезности; не заполнять квоту. Хранить начало и конец файла. Избегать самостоятельного pad из ведущей или хвостовой тишины, не обрезая PCM.
- Использовать короткое окно PCM до границы для тихого края при слабых кандидатах, проверяя оба канала. Стерео имеет одну границу. Не переносить выразительную атаку на ближайший zero crossing только одного канала. Порог тихого материала проверяет поканальную энергию и устойчивость, чтобы тихая запись или противофазное stereo не ошибочно считались тишиной.

### Материал и уверенность

| Вход | Признак выбора | Результат по умолчанию |
| --- | --- | --- |
| Короткий one-shot | Короткая длина, одна явная ранняя атака, спад | Один playable slice. |
| Drum loop | Разнесённые атаки с контрастом; иногда устойчивая сетка | Transient, Hybrid при хорошей фазе. Призвуки удара подавляются. |
| Длинный melodic loop | Устойчивая periodicity и phase; мягкие атаки | Hybrid с более крупными делениями, берегущими связные ноты. При слабой фазе меньше разрезов. |
| Vocal phrase | Паузы, тихие края; силовые пики внутри слов ненадёжны | Консервативные очевидные паузы либо целая фраза. Слова и фонемы автоматически не обещаются. |
| Chopped vocals | Повторяющиеся сильные атаки и отчётливые разделители | Transient или Hybrid при подтверждённой фазе. |
| Tonal sample | Ровная энергия и слабые атаки | Один слайс либо несколько по явным паузам. |
| Noisy / glitch | Высокая плотность и слабое различие пиков от фона | Локальный контраст и лимит плотности, при перегрузе fallback. Creative оставить явным выбором позднее. |
| Атмосфера и текстура | Нет надёжного пульса или атак | Целый источник; Equal как будущий явный режим. |

По сигналу достаточно уверенно оценивать длину, тишину, плотность атак и регулярность. Отличие вокала от синта, целостность слов, жанр и границы фраз требуют дополнительных признаков либо явного творческого выбора. V1 выбирает по наблюдаемым свойствам без классификатора и обязательных настроек.

## 4. AutoSlicePlan и владение данными

| Поле | Потребитель |
| --- | --- |
| `sampleId, sourceRevision, N, sourceRate` | Защита commit и перевод кадров в секунды. `N` и rate сверяются с текущим handle. |
| `analysisGeneration, requestId, baseSliceRevision` | Контроль и отмена задания; не нужны аудиопотоку и не служат долгоживущим ID проекта. |
| `strategy, algorithmVersion, resolvedOptions` | Повторяемость и сравнение результатов. Хранят фактические пороги, ограничения и выбранный профиль. Повторный расчёт требует того же PCM и входных признаков либо тех же версий анализаторов. |
| `tempoEvidence?` | Диагностика и объяснение выбора. Исходный BPM/confidence при наличии, при использовании сетки также реально выбранный период, phase и метрика пригодности сетки. |
| `boundaries[]` | Строго возрастающие кадры `0…N` с provenance (edge, transient, grid, hybrid, quiet gap). Опционально score для отладки и QA; это оценка, а не вероятность. Слайс выводится из пары соседних границ, дублировать start/end в плане не нужно. |
| `outcomeReason` | UI и QA различают успешную нарезку, whole-file fallback и причину. Для ошибки или отмены возвращается отдельный статус результата. |

Worker публикует immutable план без Slice IDs и MIDI slots. Commit создаёт/сопоставляет идентификаторы и MIDI, переносит параметры и хранит рядом с моделью последнее успешное auto baseline. UI получает реальные `SliceDto`, текущую revision, status и минимальную provenance; отладочные признаки остаются в C++. Playback snapshot потребляет только source handle, ID/revision, диапазоны, параметры и MIDI mapping. Для восстановления baseline в текущей сессии сохранить также исходные назначения слотов и параметры транзакции, отдельно от редактируемой коллекции.

## 5. Транзакция Slice Engine и жизненный цикл воспроизведения

1. На message thread построить staged list для ожидаемой модели; проверить диапазоны, параметры, уникальность ID, лимит и уникальность auto notes. Существующие `createSlice/splitSlice` не годятся для batch: частичный отказ оставляет предыдущие вызовы применёнными. Добавить путь prepare/commit с одной сменой revision. Подготовить playback snapshot из staging с будущей revision до смены модели. Если готовый набор идентичен текущему, вернуть no-op без новой revision.
2. Сопоставлять внутри того же источника по точному совпадению диапазонов в V1, сохранять ID, слот, ноту и параметры совпавших слайсов. Новым диапазонам выдавать монотонные ID и свободные слоты в порядке начала. Не переиспользовать ID исчезнувших диапазонов при обычной генерации. Restore baseline восстанавливает диапазоны и сохранённую раскладку, сопоставляет текущие точные совпадения и выделяет новые ID для отсутствующих. Selection следует сохранённому ID либо очищается. При смене источника всегда новая идентичность.
3. Ввести один control-thread путь к публикации и обновлению `publishedSliceRevision`. В одной message-thread операции повторно проверить ключ, передать проверенный snapshot и завершить заранее подготовленную модель через swap без аллокаций и отказов. При ошибке передачи не менять модель. UI читает только после завершения операции. Гарантия атомарности распространяется на целостность набора, принятие native-моделью и установку аудиокарты разделяет граница блока.
4. [SlicePlaybackEngine::publishSnapshot / installPendingSnapshot](../src/playback/SlicePlaybackEngine.cpp) уже передают указатель через lock-free atomic. В callback используются active/pendingInstall и фиксированные места удержания snapshot; старые указатели передаются через SPSC retirement queue и уничтожаются в `reclaimRetired()` на control thread. Замена ещё не взятого pending удаляет его на стороне publisher. При backpressure установка может быть отложена. Новые note-on сверяют requested sample/revision и могут временно не запускаться. Поэтому ACK модели не равен подтверждению playback-ready; для software pads нужен bounded статус установленного поколения или явный отказ.
5. Для того же sampleId уже звучащие голоса удерживают старый snapshot и продолжают старые границы/параметры до завершения, note-off или voice stealing. При новом sampleId активируется существующий переход с note-off/release старых голосов; старый PCM остаётся живым, пока нужен. Текущий host note-off освобождает все активные voices соответствующей ноты, в том числе при повторном назначении ноты. Это требует регрессии на перепривязку при удержании; UI pad trigger должен иметь отдельную идентичность жеста либо безопасно закрывать собственный жест до смены карты.

Тяжёлые расчёты, файловый I/O, выделение и освобождение snapshot и вызовы WebView выполняются вне audio callback. Generation/stale guard принадлежит control thread. Существующие отдельные атомики requested ID/revision нельзя считать единой атомарной парой. Проверить переходы при publish/import и полных очередях; если наблюдается пропуск note-on, сначала измерить и локализовать окно, затем рассмотреть единый install epoch в handoff. Planner не вводит второй источник публикаций.

## 6. Basic, Advanced, MIDI и pads

**Basic.** Auto после успешной загрузки в этом режиме. Пока строится kit, доступен поддерживаемый sample transport; пэды готового плана активируются после установки новой карты. Одна явная команда «Перенарезать» переиспользует валидный анализ того же источника, если доступен. При manual edits или правках параметров, которые могут исчезнуть, показать подтверждение с возможностью отмены. Форма и раскладка подчиняются утверждённому visual spec.

**Advanced.** Общая модель границ и параметров, дополненная provenance. Ручные create/split/delete/move маркируют затронутые границы как manual и не стирают auto baseline; изменения параметров не меняют provenance границ. Явный Restore auto plan применяет baseline как транзакцию с теми же проверками. Простое переключение режима и новый результат анализа не заменяют текущего плана. Открытие того же файла заново считается новым импортом с предупреждением при замене редактированного kit. Сохранение/восстановление kit по идентичности контента при повторном открытии — отдельная фаза, путь файла недостаточен.

**Раскладка.** У auto kit числовые ноты 60–91 для 32 слотов, независимо от Slice ID. Первый план заполняет слоты по времени. На повторной нарезке точные совпадения сохраняют слот; оставшиеся диапазоны заполняют свободные слоты. Поэтому повтор одинакового плана сохраняет MIDI, а действительно изменённые регионы могут получить другие назначения. Pad использует тот же slot, отдельно от хронологической оси waveform. Показывать группы по восемь при большем kit, не переназначая MIDI при смене группы. Ручные split/create внутри auto kit должны получать свободную ноту или явный конфликт, без скрытого wrap. Для старых ручных наборов оставить существующую карту, включая допускаемое наслоение, до отдельного решения о миграции. Подпись октавы зависит от хоста, числовая MIDI note является контрактом.

**Запуск.** Host MIDI уже играет регионы из snapshot. Для WebView pads нужен новый типизированный запрос с sampleId, revision и slot или sliceId, валидируемый native. Использовать ограниченную очередь control → audio с короткими командами начала/отпускания и существующим запуском voices. На приёме в callback сверять установленную revision, исключать устаревшие триггеры и гарантировать отпускание при переполнении, потере фокуса или замене карты. Определить закрытие жестов до выпуска; продумать разделение UI и host note-off. Sample Play/Stop сохраняет своё назначение. Индикация звучания требует отдельной bounded телеметрии из аудиопотока, факт выбора pad её не заменяет.

## 9. Открытые вопросы и риски

- Зафиксировать корпус и бюджет задержки. Последовательные BPM, Key и Transient могут доминировать во времени подготовки длинного источника. При необходимости дать ранний slicing-ready результат без зависимости от Key, сохранив единую идентичность поколения.
- Sparse onsets, tempo drift и octave ambiguity могут давать неверную фазу при высоком BPM score. В сомнительных случаях снижать число границ и отказываться от сетки.
- Смена ноты у изменившегося диапазона влияет на записанные MIDI партии. Точные совпадения гарантируют предсказуемость; более мягкое сопоставление по overlap требует отдельной валидации и может незаметно присвоить старый ID другому звуку.
- Текущий snapshot handoff допускает задержку установки; нужна измеримая граница готовности для pads и тесты, исключающие ошибочный запуск. Полностью бесщелчковый переход и политика release/voice stealing требуют проверки на слух.
- Проектное сохранение PCM/kit и восстановление пользовательских правок после перезапуска отсутствуют в текущем APVTS state. Зафиксировать требования к версии payload, asset identity и отсутствующему файлу отдельно.

## 10. Beat Grid Estimator — реализация UI-2.4C.3

Модуль `src/auto_slicing/BeatGridEstimator.{h,cpp}` принимает идентичность источника, frame count, sample rate и завершённый `AnalysisResult`. Он проверяет sample ID и analysis generation, валидность результата, а также совпадение геометрии transient data. Sample revision сохраняется в результате, но самого revision в `AnalysisResult` нет: вызывающая сторона обязана передать результат анализа для актуального sample/generation. Модуль не вызывает Slice Engine, Transient Planner, UI или playback.

### Что сообщает BPM Detector

`BPMAnalyzer` строит novelty envelope из RMS в полосах примерно по 10 мс, затем вычисляет нормированную автокорреляцию. Кандидаты получают поддержку по базовому периоду и соседним половинному/двойному лагам; локальный максимум уточняется параболической интерполяцией. Первичный BPM может быть поднят до более быстрого целочисленного кратного, если его score не ниже 72% от предыдущего. Octave ambiguity отмечается, когда octave-related кандидат сохраняет не менее 70% score.

`BpmAnalysis.confidence` — эвристика для периодичности, числа событий/покрытия, отделения от неоктавных кандидатов и octave penalty; это не вероятность и не оценка фазы. `score` — нормированная поддержка автокорреляции. `alternatives` содержат BPM, confidence и score, но не фазу. Детектор требует не менее 1,5 с материала, четырёх onset и трёх циклов при стандартных настройках. Оценки на более коротком материале имеют статус insufficient data; даже допустимый результат BPM сам по себе не задаёт начало такта.

### Модель, фаза и альтернативные темпы

`BeatGrid` хранит BPM, период в дробных исходных PCM frames, фазу, обе confidence оценки, reliability, diagnostic reason и список проверенных tempo hypotheses. Период вычисляется напрямую как `60 × sampleRate / BPM`. Фаза — положение импульса сетки по модулю периода в диапазоне `[0, periodFrames)`. Beat index 0 находится в этой позиции; предыдущие доли имеют отрицательные индексы. Это pulse phase, а не определение первой доли такта: без тактовой разметки и надёжного accent/meter evidence система не знает, какой beat является downbeat.

Оценщик рассматривает primary BPM и до восьми уникальных альтернатив из `BpmAnalysis`. Для каждой гипотезы он помещает вес события в круговую фазовую гистограмму из 64 bins и сглаживает ближайшие bins. Вес объединяет существующие strength, optional confidence и spectral flux; новые признаки анализа не вычисляются. Уверенность фазы считается независимо от BPM confidence: доля event weight в окне ±0,10 beat от доминирующей фазы умножается на заполнение минимального числа supporting events и минимального наблюдаемого beat span. Стандарт требует четыре события и span в три доли.

Разнесённые фазовые пики с отношением поддержки не ниже 0,78 считаются конкурирующими; тогда сетка ambiguous и точная `phaseOffsetFrames` не публикуется. Для альтернативного BPM phase fit может предпочесть гипотезу, если её phase confidence выше primary на 0,20 и detector confidence остаётся сопоставимой. Если несколько tempo hypotheses имеют близкие BPM confidence и фазовую поддержку, либо octave alternatives остаются неразличимы, результат ambiguous. Оценщик не выбирает tempo только по максимуму BPM confidence.

Reliability имеет четыре состояния: `reliable`, `ambiguous`, `unreliable`, `insufficientData`. Диагностические причины различают отсутствие BPM, слабый BPM, отсутствие transient data, малое число событий, короткий материал, усечённый список событий, слабую фазовую поддержку, конкурирующие фазы/темпы и численный предел. Неудача оценки фазы не превращается в фазу кадр 0. Manual BPM override рассматривается как заданный пользователем темп с единичной оценкой BPM, но его старые альтернативы игнорируются; фазу всё равно требуется отдельно подтвердить атаками.

### Музыкальная resolution и кадры

Поддерживаются beat, half-beat, quarter-beat, eighth-beat и sixteenth-beat. `resolution` выбирает самое мелкое деление, чей интервал остаётся не короче `minimumCandidateIntervalSeconds` (по умолчанию 60 мс). Это только resolution сетки-кандидата; она не создаёт и не предлагает готовые слайсы. Будущая Hybrid Strategy должна самостоятельно сопоставить кандидаты с минимумом Slice Engine и музыкальным контекстом.

`frameAtSubdivision()` и `frameAtBeat()` вычисляют каждую позицию от исходного phase offset и дробного периода, округляя только конечный frame. Округлённая позиция не накапливается от предыдущей. Запросы вне `[0, totalFrames)` и непредставимые позиции возвращают `nullopt`; массив позиций не строится. Оценщик ограничивает список tempo alternatives, принимает не более 65 536 transient events (максимум существующего Analyzer) и отклоняет источник свыше `2^53` PCM frames: это сохраняет точность бинарного frame coordinate. Такая длина превышает десятки тысяч лет при обычных sample rates и не ограничивает практические аудиофайлы.

### Проверки и ограничения

`BeatGridEstimatorTests` добавлен как отдельная группа и CTest `BeatGridEstimatorTests`. Синтетические сценарии проверяют метрономическую фазу, ненулевую фазу, переменную силу, пропущенные доли и слабые дополнительные атаки, конкурирующие фазы, octave ambiguity и разрешение гипотез по phase evidence, нерегулярные события, короткий и длинный материал, отсутствие ритма, слабый BPM/phase, геометрию и generation, resolution на 44,1/48/96 кГц, детерминированность и безопасную генерацию дальних/out-of-range ticks. Дополнительный сквозной сценарий подаёт фактические выходы `BPMAnalyzer` и `TransientAnalyzer` в estimator на синтетическом PCM сигнале с известными 120 BPM и ненулевым началом. Существующие `BPMAnalyzerTests` продолжают отдельно проверять детектор.

В проекте нет размеченной коллекции реальных drum и melodic loops с эталонными BPM и фазой. Поэтому эти тесты подтверждают математическое поведение и отказ при неоднозначности, но не подтверждают музыкальное качество на реальном корпусе. До Hybrid Strategy необходимо проверить phase residual и выбор octave на размеченных drum, melodic и vocal loops, включая swing, pickup, tempo drift, устойчивый offbeat и метрически неоднозначный материал. Также следует решить, нужна ли будущей модели явная meter/downbeat информация; текущая фаза намеренно описывает только beat pulse.

Beat Grid не подключён к `AutoSlicePlanner`, импорту, Slice Engine, Playback Engine, MIDI или UI. Следующий алгоритмический этап может реализовать Hybrid Strategy как отдельный planner path, который потребляет только `reliable` сетки либо явно обрабатывает `ambiguous`/fallback состояния, не меняя контракт Transient Planner.
